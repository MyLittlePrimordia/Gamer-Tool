Extract the scan sequencing, and fix the extra pass it was hiding

Phase 11 step 4 (STATE-004). The app-list scan's single-flight guard was
two fields and a loop, hand-written inside MainWindow.Slots.cs, and it
could not be tested at all: a scan of the real machine reads every Steam
library and every uninstall registry key, so there was no seam to drive
it through. Reasonable-looking was the only thing checking it.

Moved to Services/ScanCoordinator.cs, where a fake scan and a gate the
test holds open can drive every interleaving. Ten tests cover: one pass
per caller, no second concurrent scan, a mid-scan request served by a
later pass, a joining caller told it did not own the pass, several
joiners all released, three requests costing one extra pass rather than
three, sequential callers each getting their own pass, and a failed scan
neither wedging the coordinator nor stranding a joiner.

Writing those tests found two real defects.

The first: one flag cannot carry both "a pass is running" and "another
pass is wanted". The claim sets the first, so a loop reading that flag
after its own pass always saw a request nobody had made and ran one pass
too many - every caller, every time. Through the window that meant the
scan button's handler rebuilt the board from a list that had just been
replaced. Two flags now, with the reason recorded where the next reader
will hit it.

The second: the joiner was released by a wakeup that could be missed,
because the decision to wait and the registration for it were separate
steps. Both are now inside one lock, so there is no gap to be pre-empted
in.

Also fixed, found while reading it: the old form recorded a request and
had the release wipe it, in a window a few instructions wide but
reachable because every caller is on the dispatcher. The doc comment
claimed the re-arm existed for exactly that case; it did not work.

LatestWinsQueue was considered and rejected on the evidence rather than
overlooked: it drops a superseded pending request, and a force caller
wants a fresh look after the pass in flight, not instead of it.

Verified: release and debug builds clean under -warnaserror, 1513/1513
tests pass, up from 1503.
